# Security

Protected routes fail closed without OIDC configuration. Issuer discovery, RS256 signature, issuer, audience, issued-at and expiry checks precede DB subject/tenant membership lookup. Administrative roles are loaded from the database; user-supplied role claims are not trusted. The browser uses authorization code + PKCE via oidc-client-ts and session-scoped token storage. OIDC redirect URIs must be registered exactly. Sign-out clears the local session; identity-provider global logout is not implemented.

Tenant-scoped Prisma lookups and composite foreign keys protect cross-tenant references. Server-owned commercial prices use integer minor units and compatible category selections. Serializable configuration persistence records a snapshot and an audit event. Share URLs are HMAC-signed random identifiers and expose no customer identity. They are bearer capabilities: anyone holding one can read the selection and price snapshot. Response referrer policy is `no-referrer`. Link expiry, revocation and key rotation migration are still required before broad public rollout.

Express rate limiting and restricted CORS apply to the API. Limits are per API process, not Redis-distributed. Deploy behind trusted ingress with a reviewed proxy/IP policy before horizontal scaling. Lead payloads require explicit contact consent and collect no phone/address/marketing subscription. Logs omit bodies, tokens, email and share IDs; routes use templates. Error reporting strips request/user/breadcrumb fields and sends only sanitized internal error names. Telemetry and Sentry are opt-in via environment bindings; collector delivery was not validated here.

The local identity fixture is explicitly passwordless and loopback-only, generates ephemeral signing keys and refuses `NODE_ENV=production`. It exists solely for development/browser tests. Never expose it on public ingress. Production membership provisioning is an operator/bootstrap task; no default production admin credential exists.

Secrets belong in managed runtime configuration. Docker context excludes environment files and local signing keys. PostgreSQL/Redis ports bind loopback for local development. Production requires TLS database connections, least-privilege DB roles, encrypted backups, managed secret rotation and network access controls. AWS tasks consume secret ARNs; plaintext credentials are not written to Terraform variables. Protect remote Terraform state.

Remaining hardening: database RLS as defense in depth, immutable audit export and retention, lead deletion/retention workflow, distributed rate limits, full CSP with nonces, share revocation/expiry, OIDC global logout, pagination, CSRF review of any future cookie endpoints, independent penetration/accessibility testing, and observability delivery tests. These gaps are recorded, not represented as production certification.
